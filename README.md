# gaf — Grounded AI Futures

`gaf` codes open-ended survey responses the way a qualitative researcher does, and records
every step so a methods reviewer can check the work. Respondents were asked to describe one
specific, vivid scenario for AI in their society by 2050; the pipeline generates codes from
those responses rather than applying a prior scheme, develops a two-level codebook through
constant comparison, and returns a binary occurrence matrix, a hierarchical cluster
analysis over it, a saturation curve, and a dossier of what the checks could and could not
see. It is **inductive grounded theory**, run as a hybrid human–LLM procedure: two
mid-tier models from different providers code each response independently, deterministic
Python checks their work, a frontier model is consulted only where the two disagree in a
genuinely ambiguous way, and a human decides — once per checkpoint, not once per response —
how the codebook should be restructured.

> **Research question.** What are the constituent elements of global AI futures?

## Results on the principal investigator's sample

[`results/`](results/README.md) holds what the pipeline produced on his real responses,
exported as Markdown and figures. Start with [`results/README.md`](results/README.md): what
was run, what came out, and what has not been tried.
[`india-process-39-local/`](results/india-process-39-local/README.md) is the 39 responses he
coded himself, coded cold by local models, with eight comparison runs;
[`india-process-1-200-local/`](results/india-process-1-200-local/README.md) is all 200
*Process* responses coded cold. [`agreement-checks.md`](results/agreement-checks.md) puts
intervals, a chance level and a trivial predictor around the agreement figures, and
[`HOW-THE-RESULTS-WERE-REACHED.md`](results/HOW-THE-RESULTS-WERE-REACHED.md) is the run
history. The headline is modest: at the level of individual codes the machine's coding does
not line up with his (kappa between -0.065 and +0.092 across twenty measurements), and the
approved line-up of Claude Opus 5.5 with hosted Qwen has not been run, so nothing here
speaks for it. The numbered files are generated by `scripts/export_results.py` and carry counts, code
names, response numbers and metrics only, never a respondent's words. Earlier packs (the
offline stand-in coder on 200 responses, the 10 September 20-response meeting document and
the State sample) were removed from the working tree on 6 November 2026 and remain in git
history at commit `0af6528`.

## Running it

```bash
uv sync --all-groups
```

```bash
make demo
```

`make demo` materialises the synthetic corpus, codes it end to end — two coders, every
check, the router, the store — then renders the run report, the codebook explorer, the
timeline, the reorganisation trail, the decision matrix and `views.html`, and writes
everything to `runs/demo/`. **It needs no API key and no network**: the model clients are
deterministic mocks and the embedder is a lexical fallback. Run it twice and the codebook
JSON and the snapshot-id sequence are byte-identical, asserted in
`tests/test_cli.py::test_two_runs_produce_byte_identical_codebook_and_snapshots` rather
than merely claimed here.

The analysis tail is a separate target, because it is a separate deterministic pass:

```bash
make analyse       # occurrence matrix, Ward's HCA, saturation, patterns, affinity, growth -> runs/demo/analysis/
make views         # views.html standalone, from whatever of the above already exists
make check         # every check over the demo codebook; exits 1 iff an ERROR
make check-all     # ruff, mypy, and the full offline suite
```

Requires Python 3.12 (pinned in `.python-version`) and [uv](https://docs.astral.sh/uv/).

## What a run produces

`gaf run` writes the run directory; `gaf report` renders every reading artefact the run
supports — the report, both HTML pages, the timeline, the reorganisation trail and the
decision matrix; `gaf analyse` adds `analysis/`.

| File | What it holds |
|---|---|
| `codebook.html` | **open this first** — one self-contained page: every code, its family, its description, every quote with response id and span, and the findings attached to it. No script, no network request, no external asset. This is the working copy; it is not the one to share — see `views.html`, next |
| `views.html` | its shareable counterpart: eleven views of the same coding — the codebook tree, frequencies, the response-by-code heatmap, co-occurrence, patterns, affinity, growth and the timeline, the loop handover, the reorganisation trail, the crosswalk, clusters and saturation — drawn from code names, family names, response numbers, counts and scores. **No respondent text anywhere in it** |
| `tree.mmd` | the codebook as a Mermaid tree, written beside `views.html` |
| `report.txt` | the run report: caveats, provenance, the thresholds actually used, coding statistics, the codebook by family, saturation, the decision matrix's own trace for this run, and a **CHECKS** table of every finding by check and severity |
| `codebook.json` | the codebook itself — codes, descriptions, parents, evidence, and the snapshot that admitted each code |
| `assignments.json` | one row per (response, code) application, with its span |
| `findings.json` | every check finding: id, severity, scope, subject, one sentence, and a machine-readable payload |
| `stats.json` | the run report's numbers, as data — including the per-batch decision trace and, from ADR-0053, a `run_metrics` block: coder A against coder B agreement, how often the judge backed coder A, latency, and spend by role and task (the committed example predates it; `make example` regenerates it) |
| `corpus.json` | the coded corpus, with the survey question attached to every record |
| `timeline.json` / `.md` / `.svg` | when each code was born, what became of it, and what the coders saw at every batch boundary, read from the run's own audit log |
| `reorganisation_trail.json` / `.md` | one entry per checkpoint the slow loop opened: before, after, the human's verdicts, and the lineage of every code name that no longer exists. Code names, ids, counts and drop markers only — an operation's payload is filtered to keys that cannot hold text, and the keys withheld are named (ADR-0039) |
| `decision_matrix.md` | the static matrix of which loop takes which decision, rendered against this run's own thresholds |
| `audit.jsonl` | the append-only audit log for the run |
| `run.json`, `gaf.sqlite` | the full run artefact, and the blackboard it was built in |

Under `analysis/`: `clusters.md` / `clusters.json`
(cluster means and the agglomeration schedule), `saturation.md` / `saturation.json` (new
codes per batch), `patterns.md` / `patterns.json` (which responses share which code
combinations), `affinity.md` / `affinity.json` (bottom-up thematic groups of codes that
cut across families), `growth.md` / `growth.json` (code growth per batch and the spike
rule's verdict), `occurrence_matrix.json`, and `dendrogram.svg` / `saturation.svg`. A
`crosswalk.md` / `crosswalk.json` appears only when `--crosswalk-target` names a second
codebook to map this one onto.

### The commands

One CLI, nine commands: `gaf ingest | run | check | analyse | validate | report |
checkpoint | codebook | views`. `ingest` reads a response workbook or CSV into the
canonical corpus JSON, `run` is the fast loop (with flags for seeding a codebook, for
halting at the loop handover and, with `--live`, for a hard spend cap, `--max-usd`), `check` audits an artefact and is the only command that
turns an ERROR into a non-zero exit, `analyse` is the deterministic tail — matrix, Ward's
HCA, saturation, patterns, affinity, growth and an optional crosswalk — `validate` is
agreement against a human golden set plus the lexical vocabulary check, `report` renders
the report, the explorer, the timeline, the trail and `views.html` together, `checkpoint`
opens the human gate, `codebook` builds a codebook from a finished human coding and fills
in its descriptions (the Definer), and `views` builds `views.html` alone, from a run or
from a bare human coding. Usage, flags and exit codes: [`docs/RUNBOOK.md`](docs/RUNBOOK.md).

## Architecture

```
FAST LOOP — per response (cheap, parallel, stateless)
  response + its survey question
    -> deterministic prep: segmentation, dedup check, context assembly
       (top-k codes by embedding + hierarchy skeleton, from a FROZEN snapshot)
    -> Coder A (provider 1) and Coder B (provider 2), independently, identical context
    -> STRUCTURAL checks S1-S5   (deterministic; no embeddings, no LLM)
    -> SEMANTIC   checks M1-M3   (embedding-first; judge only in the grey zone)
       [S6 codebook invariants and M4 near-duplicate leaves run once, at run close]
    -> agree? accept  |  grey zone? -> Judge (frontier, provider 3)
    -> integrate (merge / create) -> write to the blackboard
    -> at every batch boundary: the DECISION MATRIX evaluates the handover
       (near-duplicates, new-code growth, the spike rule, the floor, the cadence)
       and records a verdict — it never blocks the fast loop, only reports

HANDOVER — taken by neither loop, evaluated between them, every batch
  a checkpoint comes due -> `gaf run --halt-on-checkpoint` stops at that batch boundary
    -> `gaf checkpoint` opens the HUMAN GATE below
    -> `gaf run --seed-codebook ... --skip-coded ...` resumes, coding nothing twice

SLOW LOOP — per checkpoint (rare, expensive, HUMAN-GATED)
  health + saturation metrics -> Refactorer proposes an edit script
    (split / re-parent / merge / batch-rename)
    -> HUMAN GATE: accept, reject or edit each operation
    -> apply -> new snapshot -> changelog

DEFINER — outside both loops, over a coding a person has already finished
  code-text pairings, already organised into a two-level codebook
    -> per code: its name, parent, siblings, every one of its own segments
    -> a 1-3 sentence description, grounded in that code's own text, or a refusal
  never sees a response being coded; cannot rename, merge, split or create a code

ANALYSIS TAIL (deterministic, no models)
  binary occurrence matrix -> low-frequency filter -> Ward's HCA
    -> agglomeration schedule -> cluster means
  + patterns (which responses share which codes) and affinity (bottom-up thematic
    groups of codes that cut across families); an optional crosswalk onto a second
    codebook
  respondent metadata joined ONLY here, never during coding

VALIDATION (deterministic, no models)
  human-vs-machine agreement on the golden set; L1 lexical vocabulary check
```

Two loops. Four LLM roles: Coder, Judge and Refactorer inside the two loops; the
Definer, writing a code's description from a coding a person has already finished,
outside both. One store. One deterministic tail. **Anything in that diagram without a
model name is plain Python.**

**Why the human sits at the codebook-refactor level.** Vaccaro, Almaatouq and Malone
(2024) meta-analyse 106 effect sizes and find that human–AI combinations average *worse*
than the better of the two alone (Hedges' g = −0.23, 95% CI −0.39 to −0.07), with the
losses concentrated in decision tasks and the gains in creation tasks. Item-by-item human
verification of each machine coding is exactly the decision-task overlay that finding
warns against, so this pipeline does not do it. The gate sits instead where the work is
generative and the division of labour is fixed in advance — the machine proposes an edit
script over the whole codebook, the human accepts, rejects or edits each operation — which
is less labour per checkpoint and more leverage per decision
([`docs/METHODS.md`](docs/METHODS.md) §2, ADR-0004).

## Status and limitations

The pipeline is complete and its offline path is exercised by the test suite and by CI on
every push. Real inputs have since met it: the investigator's own hand-coding of a
20-response seed sample arrived on 9 September, and his codebook definitions and the full
200-response corpus have arrived since. The pipeline has since run end to end on local models over all 200
responses ([`results/README.md`](results/README.md)). What has not happened is the hosted
run on Claude Opus 5.5 and hosted Qwen, which waits on the PI's confirmation of the two
data processors and on the API keys.

- **The thresholds are uncalibrated, and a small calibration has already run against
  that.** τ_high = 0.80, τ_low = 0.45 and τ_fit = 0.30 were set against a stand-in
  embedder. `calibrate_thresholds` has since run against the 20-response golden set
  (its write-up was in the since-removed 10 September pack, in git history at `0af6528`)
  and reports a recommendation for each — τ_high and τ_low on only 18 candidate pairs,
  which the module's own notes call too few to move a threshold on, and τ_fit on 197
  code applications whose F1 the same notes call flat from 0.45 to 1.00, meaning this
  golden set barely discriminates it either. It reports rather than silently changing a
  constant. A later calibration on a 20-response fold, repeated on the 19 held-out
  responses, put all three thresholds at about 0.95; re-running the 39 responses at
  0.90 / 0.95 / 0.90 moved agreement hardly at all ([`results/README.md`](results/README.md)). `CodingRules` in `gaf/config.py` is unchanged. The same posture holds for two
  newer families of constant: the spike rule's `spike_factor` / `spike_window` /
  `spike_min_new_codes` (ADR-0033) and affinity's blend weight and cut (ADR-0036) are
  every bit as provisional as τ_fit, and none of the three has been checked against
  human judgment. Until a calibration with enough units exists, the agreement figures
  are the harness's self-test, not findings about the study
  ([`docs/VALIDATION.md`](docs/VALIDATION.md)).
- **Offline similarity statistics describe the fallback embedder, not the codebook.** The
  code–evidence fit check (M3) does not discriminate offline — the median fit is 0.000 —
  so its warnings in a `make demo` run are artefacts. The run report says so where the
  counts appear. See ADR-0019 and ADR-0022.
- **Read the agglomeration schedule before quoting a cluster count.** The inherited rule
  assumes the largest break falls near the root of the tree; on a small sample it may not,
  and the rule then returns a degenerate answer. It was deliberately left unpatched, and
  the artefact carries the warning. See ADR-0020.
- **A seeded run is a production tool, not a validation one.** `gaf run --seed-codebook`
  codes into an organisation a person already built; its evidence is held out of the
  run, but its agreement with the coding that produced the seed is not independent
  evidence about either. Cold runs remain the validation path. See ADR-0035.
- **The investigator's own imported code descriptions are not blanket-shareable.** They
  are grounded in his coded segments and can echo their phrasing: on the real codebook,
  5 of his 131 definitions share a run of 30 characters or more with a real response,
  and the results export withholds 40 of them at its 20-character shingle.
  `organised_shareable.md` withholds the examples but still carries the descriptions
  verbatim; a results export withholds a colliding definition by code name, but a
  document built directly by `gaf codebook organise` does not. See ADR-0032, ADR-0034
  and ADR-0038.
- **The hosted live path has never been run.** Provider SDKs are optional extras that no
  test and no CI job installs, `--live` is opt-in, and every number here comes from an
  offline run. The same code path has since run on models served on this machine, first over 10
  responses (ADR-0049) and then over all 200, which showed it works end to end
  ([`results/README.md`](results/README.md)). Read the cost note in [`docs/RUNBOOK.md`](docs/RUNBOOK.md) first: offline,
  M3 accounts for the large majority of frontier calls, and whether a real embedding model
  changes that is an open empirical question (ADR-0022).

## Data

Real corpora live **outside** this repository and stay there: `data/` is gitignored except
`data/synthetic/`, every spreadsheet and document extension is excluded repository-wide,
and the only corpus committed here is the invented one in `tests/fixtures/corpus.py` that
`make demo` codes. The one deliberate exception is
[`docs/CODING_RULES.md`](docs/CODING_RULES.md), which reproduces the principal
investigator's own negative examples — his working document, kept at his explicit request,
because the coding rules are only defensible with the quotation attached. Two controls sit
on top of the `.gitignore`: `make provenance` scans every tracked file for respondent text
and fails if any file but that one shares a 20-character run with a real response — the
results exporter's own shingle, loaded from it rather than copied so the two cannot
drift (ADR-0047) — and
`make scrub` deletes `runs/` and `.gaf_cache/` — which hold the coded corpus verbatim, and
which no `.gitignore` rule protects from a zip or a directory copy — before this directory
is shared (ADR-0028).

An earlier version of this repository claimed more than that and was wrong: fixture text
drawn from real responses had been committed, and a check matching file extensions could
not see it — see ADR-0024 for what happened and what now tests the actual property.
